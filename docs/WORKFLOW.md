# 학습지 제작 워크플로 — 개요

> 선생님이 읽는 문서. 실제 작업 지시서는 `.claude/playbook/` 에 있다.
> (`.claude/` 는 GitHub Pages가 자동 제외하므로 학생에게 노출되지 않는다.)

---

## 무엇을 위한 것인가

새 과목·새 학기의 학습지와 해설지를 만들 때,
**선생님이 개입하는 지점을 2번으로 줄이기 위한** 절차와 자료 묶음이다.

2026학년도 사이클 실측: 커밋 79건 중 **30건(38%)이 수정 커밋**이었고,
선생님 발화 90건 중 약 45건이 결함 신고·방향 수정·현황 확인이었다.
이 묶음은 그 대부분을 프로세스로 흡수하는 것을 목표로 한다.

---

## 전체 흐름

```
0  스코핑        인터뷰 8문항 → 기획안 → 착수 승인      ◀ 선생님 ①
1  추출          원자료(PDF) → 문항·정답·난이도·그림
2  제작          단원별 산출물 생성
3  검증          정적 → 렌더 → 수학 → 교육과정 범위
4  통합          인덱스·모음·묶음·교사용·Nav 연동
5  감사          빠진 것 찾기
6  납품          검수보고서 → 승인 → 머지 → 드라이브    ◀ 선생님 ②
7  회고          다음을 위해 플레이북 갱신
```

**1~3은 단원 단위로 따로 굴러간다.** Ⅰ-1을 검증하는 동안 Ⅱ-1은 이미 제작에 들어간다.
한 단원이 막혀도 나머지는 계속 간다.

---

## 선생님이 하시는 일 — 두 번

### ① 착수 전 · 인터뷰 8문항

한 번에 여쭙는다. 특히 이 셋은 나중에 바꾸면 비싸다.

- **어디에 배치되나** (어느 차시 다음에?)
- **독립 차시인가, 기존 차시의 부속인가**
- **인쇄는 어디에 쓰나** (필기용 / 열람용) **어느 기기에서 저장하시나**

### ② 최종 승인 · 검수보고서

숫자로 채워진 검수표를 보시고 승인하시면, 머지와 드라이브 반영까지 자동으로 진행된다.

**그 사이에는 여쭙지 않는다.** 검증에서 문제가 나오면 스스로 고치고 다시 검증한다.

---

## 무엇이 자동으로 검사되나

| 단계 | 검사 | 이번에 잡았던 것 |
|---|---|---|
| 정적 | 문항 수·난이도·정답 필드·부등호·선택지 길이·중복 id | 정답 미표시, 수식 소실 |
| 렌더 | 브라우저에서 열고 **정답·초기화 클릭**, 그림 로드, JS 예외 | 결함 4건 동시 |
| 수학 | 정답 독립 재계산 (도전 100%, 전체 20%+) | 원본 해설 오류 |
| 범위 | 교육과정 밖 도구 사용 | 내적·톨레미 |
| 통합 | 링크 전수, 배치 일치, 합성 충돌, 인쇄 분할 | 깨진 링크 5건, QR 30개 미표시 |

## 폴더

```
.claude/playbook/          작업 지시서 (Claude가 읽는다)
  00_START.md              시작점
  10_PLAN ~ 60_RETRO       단계별 절차
  lessons/                 ★ 실제로 겪은 함정·결정·소통 교훈
  templates/               기획안·검수보고서·회고 양식
  profiles/                과목별 규칙 (범용 + 수학)

.claude/skills/
  worksheet-pipeline/      전체 파이프라인 오케스트레이션
  exam-solution-sheet/     해설지 1건 생성

.claude/agents/            도메인 에이전트 6개 → docs/agents.md

scripts/
  verify_sheet.py          정적 검증
  verify_render.js         렌더 검증
  verify_links.py          링크 전수 + 중복 id 검사
```
