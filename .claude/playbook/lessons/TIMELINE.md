## 시간이 샌 곳 — 실측 상위 5

### 1위. 수정 커밋 — **87건 중 32건 (37%)**

한 번에 맞춘 게 아니라 **10번 중 4번은 고치러 다시 왔다.**

| 영역 | 수정 PR |
|---|---|
| 인쇄·PDF | 6건 |
| 교육과정 이탈 풀이 | 5건 |
| 렌더 결함 | 3건 |
| 문서 합성 충돌 | 3건 |
| 링크·경로 | 2건 |

→ **검증 게이트(30_VERIFY)가 이 38%의 대부분을 흡수한다.**

### 2위. 큰 파일 Read 실패 — **도구 오류 39건 중 33건 (85%)**

학습지 HTML은 한 파일이 8만~18만 토큰. 통째로 읽을 수 없는데 계속 시도했다.

→ **`grep -n` + Python 슬라이스로 고정** (PITFALLS F-4).

### 3위. "정본이 어디인가" 혼란 — 선생님 발화 **8회**

드라이브 사본과 저장소 정본이 엇갈렸다. 확인·설명·재전송이 반복됐다.

→ **작업 시작 전 정본 확정 한 문장** (COMMUNICATION 5).

### 4위. 일괄 적용 누락 — 최소 3회 재작업

한 파일만 고치고 끝냈다가 "나머지에도 적용해줘"를 들었다.

→ **고치기 전에 "같은 파일이 몇 개인가"를 센다** (PITFALLS B-1).

### 5위. 인쇄 요구 왕복 — 발화 5회, PR 6건

"화면에서 본 그대로"라는 기준을 늦게 파악했다.

→ **인터뷰 7번 문항 + "화면 레이아웃을 그대로 인쇄 CSS로"** (DECISIONS D-5).

## 진행 순서 (실제)

```
1학기 대수 (5~6월)
  학습지 18개 → 타이머·위젯 → 도전문제 큐레이션(에이전트 도입)
  → 교사용 Nav 18차시 → 수능특강 해설 정정(교육과정 이탈 5건)

  풀이공간 모달 강화 → PDF 저장(요구 왕복 5회, PR 6건)
  → 학습지 18개 일괄 적용 → 전체 묶음 PDF

2학기 미적분 I (7월)
  뽑기 3모드 → 드라이브 동기화 혼란(발화 8회) → 성찰지 폼 모음
  → 해설지 생성 스킬화 → 수능특강 별도 배포(Netlify)
  → 수학 익힘책 6단원(70문항) → 묶음 반영 → 위젯 정리
  → 플레이북 패키지화 ← 지금
```

**관찰** 후반으로 갈수록 **스킬·에이전트·스크립트로 고정**되면서 속도가 붙었다.
익힘책 6단원(70문항)은 앞선 사이클 대비 훨씬 빠르게 끝났다.
이 플레이북은 그 흐름의 연장이다.
