## A. 콘텐츠 정합성

### A-1. 렌더 검증 생략 → 결함 4건 동시 발생 ★최대 사고 `#97`

  > 캡처되었고, 정답을 눌렀으나 정답이 표시되지 않음 / 사진3: 수식이 이상하고 STEP의 배치가

### A-2. 필드명 불일치 — `answer` vs `answerText` `#97`

- **증상** 정답 버튼을 눌러도 아무것도 안 나옴. **에러도 안 난다.**

### A-3. 부등호 `<` `>` 가 HTML 태그로 먹힘 `#97`

### A-4. 5열 그리드 선택지 넘침 `#97`

## C. 인쇄 · PDF · 레이아웃

이 영역만 **수정 PR 6건**이 나왔다. 가장 예측이 어려운 영역이다.

### C-1. 인쇄 요구는 한 번에 안 잡힌다 `#71 #72 #73`

- **경과** "풀이공간 펼친 채로 저장 가능?" → "**화면에서 본 그 형식 그대로** 저장하는 것이었어"
  → 디자인 개선 3건 → "한 페이지 원칙은 필기용에만"
- **교훈** 사용자의 기준은 **"화면에서 본 그 모습"**이다.
  새 인쇄 레이아웃을 설계하지 말고, **화면 모달의 레이아웃을 그대로 인쇄 CSS로 옮긴다.**

### C-2. 인쇄 모드별로 정답 하이라이트가 달라야 한다 `#76`

- **증상**
  > "필기를 위한 pdf 저장할 때에, 문제 보기에 정답이 초록색으로 테두리 칠해진 채로 저장되는 거 같아"
- **방지** 정답 강조는 **해설 모드에서만.** 문제만/필기공간 모드에서는 제거.

### C-3. 인쇄 CSS는 기기마다 다르게 동작한다 `#78 #79`

- **증상** PC에서 페이지 단절을 잡았는데
  > "태블릿에서 저장하려고하니 pc에서와는 또 다르네 단절되는부분이 없는지 다시 확인부탁해"
- **원인** iOS Safari의 인쇄 엔진이 다르다. 가상 요소(`::before`) 기반 여백이 무시됐다.
- **방지** ① 인쇄용 여백·구분은 **가상 요소 대신 실제 DOM 요소**로
  ② 세로/가로(orientation) 적응형으로
  ③ **"어느 기기에서 저장하시나요"를 미리 묻는다** (`10_PLAN.md` 인터뷰 7번)

### C-4. 문항이 페이지 경계에서 잘림

- **방지** `break-inside: avoid` + **인쇄 미디어에서 실제 높이 측정**
  ```js
  await page.emulateMedia({ media: 'print' });
  const PAGE = 1122 - 2*53;   // A4 297mm − 여백 14mm×2 ≈ 1016px @96dpi
  ```

### C-5. `overflow: auto` 가 인쇄에서 내용을 삼킨다 ★조용히 사라진다

- **증상** 화면에서 카드 밖으로 넘친 긴 수식이 **PDF에서 통째로 사라짐.**
  화면에는 스크롤바가 있어 밀어 볼 수 있으니 정상으로 보인다.
  > "흰 배경 밖으로 설명·해설이 넘쳐서 나오는데, pdf로 변환시 잘리는 것인가?"
- **원인** `.q-stmt`/`.q-solve` 의 `overflow-x: auto`. **인쇄에는 스크롤이 없다.**
  (덤: `overflow-x: auto` 만 지정해도 `overflow-y` 가 `auto` 로 계산되어 세로 스크롤바까지 생긴다)
- **더 큰 원인** `@media print { .problems { grid-template-columns: 1fr } }` 로 1단 전환을 걸어 놨어도
  `.prob-card.span2 { grid-column: span 2 }` 가 살아 있으면 **1단 그리드에 2열이 다시 생긴다.**
  인쇄에서도 카드가 절반 폭에 머물러 잘림이 2배로 심해진다.
- **방지** 인쇄 블록에서 span 해제 + 넘침 허용:
  ```css
  @media print {
    .problems { grid-template-columns: 1fr; }
    .prob-card.span2 { grid-column: auto !important; }   /* ← 빠지기 쉽다 */
    .q-stmt, .q-solve, .q-ans, .q-warn, .step-body, .calc {
      overflow: visible !important; word-break: break-word;
    }
    mjx-container { max-width: 100% !important; }
  }
  ```
- **검증법** 폭을 아는 표식을 주입해 실제 PDF에서 살아남는 한계를 잰다.
  화면 측정만으로는 못 잡는다.
  ```js
  // 카드에 폭 300~1000px 표식(S{w}S … E{w}E)을 넣고 page.pdf() → 텍스트 추출
  // 끝 표식이 사라지는 폭이 곧 잘림 한계
  ```
  실측(A4 세로, 여백 14mm): **수정 전 600px → 수정 후 950px**

  ⚠️ 샌드박스는 프록시가 MathJax CDN을 막으므로(403) 수식이 실제로 렌더되지 않는다.
  **폭 표식 주입 방식이 유일하게 신뢰할 수 있는 측정법**이고, 최종 육안 확인은 사용자 화면에서 받아야 한다.

### C-6. CSS 규칙을 "추가"하면 뒤에 있는 원본이 덮어쓴다 ★두 번 당함

- **증상** `.problems`를 1단으로 바꾸고 `.prob-card.span2 { grid-column: auto }`를 **추가**했더니
  폭이 오히려 **3가지(175 / 693 / 880)로 늘어남.**
- **원인** 원본 `.prob-card.span2 { grid-column: span 2 }` 가 **내 규칙보다 뒤에** 있었다.
  같은 특이도면 **나중 규칙이 이긴다.**
  게다가 `grid-template-columns: 1fr` 인 그리드에 `span 2` 항목이 있으면
  **암묵적 2열이 새로 생겨** 1단 전환 자체가 무력화된다.
- **방지** 기존 규칙을 바꿀 때는 **추가하지 말고 원본을 직접 교체**한다.
  `!important` 로 이기려 들면 인쇄·다크모드 등 다른 미디어 쿼리와 또 충돌한다.
  적용 후 **실제 렌더 폭을 재서** 고유값이 1개인지 확인한다.

### C-7. 합성 문서에서 원본의 숨김 규칙이 새 구조를 무력화한다

- **증상** 묶음에 목차·이전·다음 앵커를 넣었는데 **화면에 아무것도 안 보임.**
- **원인** 묶음 빌더가 `.aft-lesson-wrap nav.no-print { display: none !important }` 로
  섹션 내 상단 내비를 **통째로 숨겨** 놨다. 외부 파일을 가리키던 시절엔 맞는 조치였다.
- **방지** 합성 문서에 새 UI를 넣기 전에
  **그 요소를 숨기는 기존 규칙이 있는지 먼저 확인**한다.
  `getComputedStyle(el).display` 를 재보면 즉시 드러난다.
  구조를 바꿨으면 **그때 만들어진 숨김 규칙도 같이 갱신**해야 한다.

### C-8. 그리드 항목의 `min-width: auto` 가 카드를 통째로 늘린다 ★측정까지 속인다

- **증상** 통합본에서 특정 차시의 문항 카드만 **옆으로 튀어나옴.** 개별 파일에서는 멀쩡.
  > "10차시 내에서는 괜찮은데, 묶음에서 보면 10차시의 E 파트만 옆으로 더 튀어나왔어"
- **원인 ①** 통합본 컨테이너가 개별 파일보다 좁았다 (`max-width: 760px` vs `.lesson` 880px).
  같은 수식이 개별에서는 들어가고 통합본에서만 넘친다.
- **원인 ②** 그리드 항목은 기본이 `min-width: auto` 라 **내용이 넓으면 항목 자체가 늘어난다.**
  카드가 늘어나면 그 안을 재는 스크립트도 "안 넘쳤다"고 판정한다 — **측정까지 속는다.**
- **방지**
  ```css
  .aft-lesson-wrap { max-width: 952px; }        /* 통합본 = 개별 파일과 같은 카드 폭 */
  .problems > .prob-card { min-width: 0; }      /* 그리드 항목이 늘어나지 않게 */
  ```
  통합본을 만들면 **개별 파일과 카드 폭이 같은지 반드시 측정**한다.
  같지 않으면 개별에서 통과한 검증이 통합본에서 무효가 된다.

### C-9. 폭은 고정하고 수식을 줄인다 — `transform` 말고 `font-size`

- **원칙** 카드 폭은 고정한다. 안 들어가는 수식이 양보한다.
- **`transform: scale()` 금지** 레이아웃 박스가 줄지 않아 **인라인 수식이 옆 글자와 겹친다.**
  실제 사례의 수식은 `<span class="step">(4) 삼중곱 \(…\)</span>` 처럼 문장 안에 있었다.
- **`font-size` 축소** CHTML 의 레이아웃 박스까지 함께 줄어 부작용이 없다.
  ```js
  var avail = 가장 가까운 블록 조상의 clientWidth;
  var w = c.getBoundingClientRect().width;
  if (w > avail) c.style.fontSize = Math.max(55, Math.floor(100*avail/w) - 1) + '%';
  ```
  MathJax 조판 완료 후 · 창 크기 변경 시 · `beforeprint` 에 각각 실행.
- **검증법** CDN 이 막혀 수식을 못 그리면, **폭을 아는 가짜 `mjx-container` 를 심어** 로직만 검증한다.
  실측: 1020px → 82%로 836px, 1530px → 55%(하한)로 842px, 765px 이하는 손대지 않음.

### D-4. 드라이브에 올린 HTML은 상대 링크가 동작하지 않는다

- **증상**
  > "모바일로 구글드라이브에서 NAV파일 열고 링크 클릭하면 오류가 뜨는데 그거 정상인거야?"
- **원인** 드라이브 미리보기 뷰어는 파일을 **격리해서** 보여준다. 옆 파일을 못 찾는다.
- **방지** 드라이브는 **보관·전달용**, 실제 사용은 **GitHub Pages 등 웹 배포본**으로.
  파일을 드릴 때 이 차이를 **미리** 안내한다.
  오프라인이 필요하면 **통합본 1개**를 쓴다 (링크 자체가 불필요).
  단 외부 CDN(MathJax)을 못 받아 수식이 깨지므로 완전 오프라인은 CDN 임베드가 별도로 필요하다.

### D-5. 정본이 어디인지 모르는 상태 ★가장 큰 시간 낭비

- **경과** 드라이브 파일이 "틀만 잡힌 미완성본"이고 깃이 완성본인데,
  선생님은 드라이브 것을 정본으로 알고 계셨다. 확인·설명·재전송에 **발화 8회**가 소모됐다.
  > "그거 파일 3개만 있다고 다시 작업해야된다며?"
- **방지** 사본이 여러 곳(깃 / 드라이브 / 로컬)에 있으면
  **작업 시작 전에 "무엇이 정본인가"를 한 문장으로 확정**하고 공유한다.
  이후 모든 전달은 정본에서 파생시킨다.

### D-6. 드라이브 MCP 는 갱신·삭제가 안 된다

- **증상** 올린 뒤 오타를 발견해도 되돌릴 방법이 없다. 같은 이름으로 다시 올리면 **중복 파일**이 생긴다.
- **원인** `create_file`·`copy_file`·`search_files` 만 있고 update/delete 가 없다.
  서버가 바뀌면 **파일 ID 가 안 맞아** `copy_file`·`search_files` 도 실패한다.
- **방지** **올리기 전에 내용을 확정**한다. 지표·항목 수 같은 숫자는 업로드 직전에 다시 센다.

## E. 문서 합성 (여러 파일을 하나로 묶을 때)

여러 HTML을 합치면 **각 파일의 전역이 전부 충돌한다.** 세 종류가 한꺼번에 터졌다.

### E-1. `const` 전역 재선언 `#103`

- **증상** `Identifier 'GOOGLE_FORM_BASE_URL' has already been declared` × 30.
  **두 번째 이후 섹션의 스크립트 블록이 통째로 실행되지 않음.**
- **방지** 각 섹션 스크립트를 **IIFE로 감싸고**, 공유 값은 `window.NS[섹션키]` 로.

### E-2. DOM id 중복 → 첫 번째만 동작 ★발견이 가장 늦음 `#103`

- **증상** 성찰지 QR·폼 링크가 **01차시에만** 표시. 나머지 30개는 빈 칸.
  (1학기 묶음은 더 나빴다 — 18개 핸들러가 서로 덮어써 **0 / 18** 이 표시됐다)
- **원인** `id="qr-container"` 가 31개. 31개 핸들러가 전부 첫 번째 요소에 써넣었다.
- **방지** id에 **섹션 키를 접미**하고 DOM 조회를 섹션 스코프로. **중복 id 검사 자동화.**

### E-3. `position:fixed` 위젯이 N겹으로 겹침 `#104 #105`

- **증상** 플로팅 버튼 그림자가 여러 겹으로 번져 보임.
  > "무언가 여러개 겹쳐보이지 않아?"
- **방지** 합성 시 화면 고정 요소는 **1벌만 남기거나 전부 제거.**

### E-4. 로딩이 멈춘 것처럼 보임 `7c1ea2f`

- **원인** `body { opacity: 0 }` 로 두고 MathJax 완료 시 켜는 패턴.
  합성 문서는 조판이 오래 걸려 **빈 화면이 수 초간** 유지된다.
- **방지** 합성 문서에서는 opacity 의존을 제거하고 처음부터 보이게 한다.

### E-5. 합성본에는 내부 이동 수단이 필요하다

- **증상** 37차시가 한 파일에 있는데 **목차·앵커가 0개**라 30차시를 보려면 스크롤로 찾아야 했다.
  게다가 각 섹션의 "다음 차시" 링크가 **외부 파일**을 가리켜 오프라인에선 전부 죽었다 (123개).
- **방지** 합성 시 **섹션마다 id 부여 + 상단 목차 + 이전/다음 내부 앵커**를 함께 만든다.
  외부 링크는 최소로 남기고, 남긴 것은 "온라인에서만 유효"임을 알린다.

## F. 작업 환경 · 도구

### F-1. 머지 중 폴더 통째 삭제 ★위험도 최고

- **증상** `git diff origin/main --stat` 에 `-54,621` 줄. 교사용 75개 파일이 삭제 스테이징.
- **방지** **커밋 직전 항상**
  ```bash
  git diff origin/main --diff-filter=D --name-only
  git diff origin/main --stat | tail -3
  ```
  복구는 `git checkout origin/main -- "<경로>"`.

### F-2. `.gitignore` 가 새 파일을 삼킴

- **증상** `The following paths are ignored by one of your .gitignore files: build_bundle.py`
  `.claude/playbook/` 도 같은 이유로 커밋되지 않을 뻔했다.
- **방지** 새 폴더·새 확장자를 만들면 **예외 규칙을 같이 추가**한다.
  `git add` 실패 메시지를 그냥 넘기지 않는다.

### F-3. PR 머지 충돌 405

- **증상** `405 Pull Request has merge conflicts`
- **방지** 푸시 전 `git fetch origin main` 으로 최신 상태 확인.
  직전 PR이 머지되었으면 브랜치를 최신 main에서 다시 시작한다.

### F-4. 큰 파일 Read 실패 — **도구 오류 39건 중 33건** ★압도적 1위

- **증상** `File content (184986 tokens) exceeds maximum allowed tokens (25000)`
- **원인** 학습지·묶음 HTML은 한 파일이 8만~18만 토큰이다. 통째로 읽을 수 없다.
- **방지** 큰 HTML은 **절대 Read로 통째 열지 않는다.**
  - 구조 파악 → `grep -n` 으로 위치만
  - 내용 확인 → Python으로 필요한 구간만 슬라이스
  - 수정 → Edit(부분 치환) 또는 빌드 스크립트 재생성
  ```python
  s = open(f, encoding='utf-8').read()
  i = s.find('<마커>'); print(s[i:i+2000])
  ```

### F-5. 환경 의존성 가정 금지

- **증상** `ModuleNotFoundError: No module named 'numpy'`
- **방지** 표준 라이브러리로 되는 일은 표준 라이브러리로. 설치가 필요하면 먼저 확인한다.

### F-6. 셸 작업 디렉터리 드리프트

- **증상** `cd 교사용 && grep ...` 성공 후, 다음 명령이 엉뚱한 위치에서 실패.
- **방지** **절대경로.** `cd` 는 그 명령 안에서만 끝낸다.

### F-7. 샌드박스에서 외부 CDN 로드 실패

- **증상** Playwright `page.goto` 90초 타임아웃.
- **방지** 검증 스크립트에서 MathJax·Tailwind·Fonts를 스텁으로 가로챈다.
  **수식이 raw TeX로 보이는 것은 정상이다.**

### F-8. Playwright 브라우저 버전 불일치

- **방지** `executablePath` 명시. `playwright install` 실행 금지 (이미 설치돼 있다).
