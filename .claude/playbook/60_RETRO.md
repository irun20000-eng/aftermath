# 6단계 · 평가 — 회고와 플레이북 갱신

> 작업이 끝나면 **반드시** 이 단계를 한다. 안 하면 다음 사이클에 같은 함정을 다시 밟는다.
> 이 플레이북 자체가 이 단계의 산출물이다.

---

## 회고 3문항

`templates/회고.md` 를 채운다.

### 1. 무엇이 터졌나

작업 중 **수정 커밋을 남긴** 모든 결함. 사소해 보여도 적는다.

| 결함 | 증상 | 원인 | 어느 단계에서 잡았어야 했나 |
|---|---|---|---|
| | | | |

→ "잡았어야 했던 단계"가 곧 **검증 게이트에 추가할 항목**이다.

### 2. 어디서 방향이 바뀌었나

선생님 피드백으로 되돌린 작업.

| 처음 한 것 | 바뀐 것 | 선생님의 말 | 착수 전에 물었으면 막을 수 있었나 |
|---|---|---|---|
| | | | |

→ "막을 수 있었다"가 **예**면 `10_PLAN.md` 인터뷰에 질문을 추가한다.

### 3. 무엇이 반복 노동이었나

세 번 이상 손으로 한 것.

| 반복한 일 | 횟수 | 자동화 가능? |
|---|---|---|
| | | |

→ 자동화 가능하면 `scripts/` 에 스크립트를 남긴다.

---

## 플레이북 갱신

회고 결과를 이 폴더에 **즉시** 반영한다. "나중에"는 오지 않는다.

| 회고 결과 | 갱신 대상 |
|---|---|
| 새로 터진 결함 | `lessons/PITFALLS.md` — 증상·원인·방지 3줄 |
| 검증에서 놓친 항목 | `30_VERIFY.md` + `scripts/verify_*.py` |
| 방향이 바뀐 결정 | `lessons/DECISIONS.md` + `10_PLAN.md` 인터뷰 |
| 반복 노동 | `scripts/` 에 스크립트 추가 |
| 새 과목 | `profiles/<과목>.md` 신설 |
| 산출물 양식이 바뀜 | `.claude/skills/` 의 템플릿 |

## 지표

사이클마다 기록해 두면 개선이 눈에 보인다.

| 지표 | 2026학년도 (실측) | 다음 사이클 목표 |
|---|---|---|
| 커밋 | 79 | |
| **수정 커밋 비율** | **38% (30/79)** | **10% 이하** |
| 선생님 발화 | 90 | |
| ├ 결함 신고 | 약 15 | **0~2** |
| ├ 방향 수정 | 약 10 | **0~1** |
| └ 현황 확인 | 약 20 | **5** |
| 도구 오류 | 39 (85%가 큰 파일 Read) | **10 이하** |

전체 실측은 `lessons/TIMELINE.md`.

> **핵심 수치: 커밋 10건 중 4건이 고치러 다시 온 것이었다.**
> 검증 게이트(30_VERIFY)와 스코핑 인터뷰(10_PLAN)가 이 대부분을 흡수한다.

## 이번 사이클 회고 (2026-2학기 · 수학 익힘책 6단원)

**터진 것** — `lessons/PITFALLS.md` 15건으로 정리 완료
가장 비쌌던 것: 렌더 검증 생략(결함 4건 동시), 문서 합성 충돌 3종, 머지 중 폴더 삭제

**방향 전환** — `lessons/DECISIONS.md` 6건으로 정리 완료
가장 중요한 선례: **지적을 받으면 "고칠까"보다 "왜 있나"를 먼저 묻는다**

**반복 노동**
| 반복한 일 | 대응 |
|---|---|
| 정적 검사(필드명·부등호·카운트) | `scripts/verify_sheet.py` |
| 렌더 검증 | `scripts/verify_render.js` |
| 링크 전수 검사 | `scripts/verify_links.py` |
| zip 만들어 전송 → 수동 덮어쓰기 | **Google Drive MCP 자동 업로드**로 대체 |
| 교사용 사본 수작업 | `20_BUILD.md` 의 기계적 변환 절차 |

**다음 사이클에 가장 크게 바뀔 것**
- 렌더 검증이 **필수 게이트**가 되어 결함 신고가 사라진다
- 스코핑 인터뷰 8문항으로 방향 전환이 사라진다
- 드라이브 자동 업로드로 전송 왕복이 사라진다
