# 3단계 · 검증 — 4단 게이트

> **생략 금지.** 이번 사이클 최대 사고(결함 4건 동시 발생)는 이 단계를 건너뛴 결과다.
> A만 통과하고 B를 안 하면 화면이 깨진 채로 납품된다.

```
A 정적 검사   ─ 파일을 읽어서 규칙 위반 탐지      (초 단위)
B 렌더 검증   ─ 브라우저에서 실제로 열고 클릭     (수십 초)  ★가장 중요
C 수학 검증   ─ 정답을 독립적으로 재계산
D 범위 검사   ─ 교육과정 밖 도구 사용 여부
─────────────────────────────────────────
E 통합 검사   ─ 통합 단계 후 1회 (링크·중복 id·인쇄)
```

**단원 하나가 제작되면 즉시 A~D를 돌린다.** 전체를 다 만든 뒤 몰아서 하지 않는다.
실패하면 **스스로 고치고 재검증**한다. 선생님께 묻지 않는다.

---

## A. 정적 검사

```bash
python3 scripts/verify_sheet.py <파일> --expect-count 11 --expect basic=3,standard=6,advanced=2
```

검사 항목:

| # | 항목 | 실패 시 |
|---|---|---|
| 1 | 문항 수가 기대치와 일치 | 누락·중복 문항 확인 |
| 2 | 난이도 분포가 기대치와 일치 | 라벨 오기입 |
| 3 | `type`별 정답 필드 존재 (`choice`→`answer`, `short`→`answerText`) | ★ 정답이 화면에 안 나옴 |
| 4 | 수식 안 raw `<` `>` 없음 | ★ 수식이 통째로 사라짐 |
| 5 | 선택지 길이 20자 이하 | 그리드 넘침 |
| 6 | 외부 이미지 참조(`src="images/...`) 없음 | 배포 시 그림 깨짐 |
| 7 | 필터 카운트 = 실제 문항 수 | 표시 불일치 |
| 8 | `id` 중복 없음 | 첫 번째만 동작 |

## B. 렌더 검증 ★

```bash
node scripts/verify_render.js <파일> [확인할 문항 수]
```

**브라우저에서 실제로 열고 클릭한다.** 정적 검사로는 절대 잡히지 않는 것들:

| # | 확인 | 왜 |
|---|---|---|
| 1 | 문항이 실제로 렌더됨 | JS 오류로 빈 화면이 될 수 있다 |
| 2 | **정답 버튼 클릭 → 정답 표시** | 필드명이 틀리면 조용히 아무 일도 안 일어난다 |
| 3 | **초기화 클릭 → 정답 사라짐** | 리셋 누락이 실제로 있었다 |
| 4 | 그림이 로드됨 (`naturalWidth > 0`) | base64가 깨졌을 수 있다 |
| 5 | JS 예외 0건 | 콘솔 에러 |
| 6 | 빈 문제 없음 | 템플릿 치환 실패 |

**샌드박스에서는 CDN이 차단**되므로 스크립트가 MathJax·Tailwind를 스텁한다.
→ 수식이 raw TeX(`\(9\)`)로 보이는 것은 **정상**이다. 실제 브라우저에서는 렌더된다.

## C. 수학 검증

정답을 **원본 해설과 독립적으로** 재계산한다.

- 도전 문항: **100%**
- 전체: **20% 이상**
- 원본 해설의 OCR 깨짐·오탈자를 그대로 옮기지 않는다

> 확신이 서지 않으면 `problem-evaluator` 에이전트를 불러 교차 검증한다.
> 더 강하게 하려면 **서로 다른 관점의 검증자 3명**에게 각각 "이 정답을 반박해 보라"고 시키고
> 2명 이상이 반박하면 재계산한다.

## D. 교육과정 범위 검사

해설이 **그 과목에서 배우지 않은 도구**를 쓰지 않았는지 본다.
수학적으로 맞아도 학생이 못 따라오면 해설이 아니다.

- 과목 `profiles/` 의 **허용 도구 목록**과 대조
- 이번 사이클 실제 사례: 내적·톨레미 정리 → 2026 대수 교육과정 밖 → 코사인법칙으로 재작성

## E. 통합 검사 (통합 단계 후 1회)

```bash
python3 scripts/verify_links.py            # 링크 전수 검사
node    scripts/verify_render.js <묶음>     # 합성 문서 렌더 검증
```

| # | 항목 | 이번에 걸린 것 |
|---|---|---|
| 1 | 모든 `href`의 대상 파일이 실제로 존재 | 5건 (오타 2 + 폴더 깊이 3) |
| 2 | 배치 순서가 학생용·교사용·묶음 **세 곳 모두 일치** | — |
| 3 | 합성 문서에 **중복 id 없음** | 10종 × 30개 |
| 4 | 합성 문서에 `const` 재선언 없음 | 31회 → JS 예외 30건 |
| 5 | `position:fixed` 요소가 의도한 개수만 | 3종 × 31벌 겹침 |
| 6 | 인쇄 시 문항이 페이지를 넘지 않음 | 측정으로 확인 |
| 7 | **인쇄 시 가로로 잘리는 내용 없음** | 폭 표식 주입 → PDF 텍스트 잔존 확인 |

### 인쇄 분할 측정

```js
await page.emulateMedia({ media: 'print' });
const PAGE = 1122 - 2*53;                  // A4 297mm − 여백 14mm×2 (≈1016px @96dpi)
const tall = [...document.querySelectorAll('.문항선택자')]
  .map(el => el.getBoundingClientRect().height)
  .filter(h => h > PAGE);
// tall.length === 0 이어야 한다
```

## 검증 보고

`templates/검수보고서.md` 를 채워 선생님께 제시한다. **숫자로 적는다.**

```
문항 수         70 / 70          ✅
난이도 분포     기초18 기본37 도전15  ✅ (기획 일치)
정답 필드 누락  0건               ✅
raw 부등호      0건               ✅
그림 로드       12 / 12           ✅
JS 예외         0건               ✅
초기화 동작     6 / 6 파일        ✅
링크 검사       644개 중 깨짐 0    ✅
인쇄 분할       0건 (최대 989px < 1016px) ✅
정답 재계산     15 / 70 (도전 전량 포함) ✅
```

**"확인했습니다"가 아니라 "70/70"이라고 쓴다.** 숫자가 없으면 검증한 게 아니다.
