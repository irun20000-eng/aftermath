# 5단계 · 납품 — 머지와 드라이브 반영

> **선생님 개입 지점 ②.** 검수보고서를 제시하고 승인을 받은 뒤, 여기부터는 자동.

---

## 순서

```
검수보고서 제시 → 승인 → PR 생성 → squash 머지 → 드라이브 업로드 → 완료 보고
```

---

## 1. 머지

```bash
git push -u origin <branch> --force-with-lease
```

네트워크 오류면 2s → 4s → 8s → 16s 로 최대 4회 재시도.

PR 생성·머지는 GitHub MCP 도구 사용 (`create_pull_request`, `merge_pull_request`).
**머지 방식은 squash.** 브랜치 히스토리가 main을 어지럽히지 않는다.

---

## 2. 구글 드라이브 반영

**정책: 새 폴더에만 자동 업로드.** 기존 파일은 건드리지 않는다.
선생님이 확인한 뒤 직접 옮기신다. 되돌리기 사고가 원천 차단된다.

### 절차

1. 드라이브에서 대상 폴더를 찾는다

   ```
   mcp__Google_Drive__search_files
     query: "title contains 'aftermath' and mimeType = 'application/vnd.google-apps.folder'"
   ```

2. 그 아래 **날짜·작업명 폴더**를 만든다 — 예: `_배포_20270301_공통수학1_익힘책`
3. 산출물을 업로드한다 (학생용은 루트, 교사용은 `교사용/` 하위 구조 유지)
4. 폴더 URL을 선생님께 알려 드린다

### 업로드 대상 정리

| 구분 | 대상 |
|---|---|
| 신규 | 이번에 만든 학생용·교사용 산출물 전부 |
| 갱신 | 링크·인덱스가 바뀐 기존 파일 (인덱스, 모음, 묶음, 교사용 인덱스, Nav 인덱스) |
| 제외 | 빌드 스크립트, 중간 산출물, 원자료 PDF |

**갱신 대상을 빠뜨리기 쉽다.** 통합 단계에서 수정한 파일 목록을
`git diff --name-only <merge-base>..HEAD` 로 뽑아 그대로 쓴다.

### zip으로 보낼 때 (드라이브 접근이 안 될 때)

```python
import zipfile, os
with zipfile.ZipFile(out, 'w', zipfile.ZIP_DEFLATED) as z:
    for f in files:
        z.write(f, f)                      # 폴더 구조 유지
```

셸 `zip` 명령을 쓰지 않는다 — 한글 파일명이 깨진다 (PITFALLS B-2).

## 3. 완료 보고

선생님께 드리는 마지막 메시지에 반드시 담는다.

| 항목 | 내용 |
|---|---|
| 만든 것 | 산출물 목록 + 문항 수 |
| 배치 | 어디에 어떤 순서로 들어갔는지 |
| 검증 | **숫자로** |
| 판단한 것 | 묻지 않고 정한 것과 그 근거 (한 줄씩) |
| 안 한 것 | 범위 밖이라 남긴 것, 발견했지만 손대지 않은 별건 |
| 반영 위치 | 드라이브 폴더 URL 또는 zip |

**"판단한 것"과 "안 한 것"을 빠뜨리지 않는다.**
선생님이 나중에 발견하는 것보다 지금 알리는 편이 훨씬 낫다.

---

## 4. 배포 (선택)

별도 사이트로 배포하는 경우 (예: 수능특강 해설 → Netlify):

- **모든 그림은 base64 임베드**되어 있어야 한다. 아니면 배포본에서 깨진다
- 배포본의 "메인" 링크는 **그 사이트의 인덱스**를 가리켜야 한다.
  저장소 메인을 가리키면 404가 난다
- 같은 주소로 재배포하면 URL은 유지된다
