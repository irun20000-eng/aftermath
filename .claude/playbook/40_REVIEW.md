# 4단계 · 리뷰 — 커밋과 PR

---

## 커밋 전 안전 점검 ★

**이 두 줄을 항상 먼저 돌린다.** 머지 과정에서 교사용 폴더 75개 파일이 삭제 스테이징된 사고가 있었다.

```bash
git diff origin/main --diff-filter=D --name-only   # 삭제되는 파일 — 비어 있어야 정상
git diff origin/main --stat | tail -3              # 총 증감 — 삭제 줄 수가 비정상이면 중단
```

의도하지 않은 삭제를 발견하면:

```bash
git checkout origin/main -- "<경로>"
```

`.gitignore` 를 건드렸다면 **반드시** 위 검사를 다시 한다. 무시 규칙 한 줄이 추적 파일을 삭제로 만든다.

---

## 브랜치 규칙

- 지정된 작업 브랜치에서만 작업한다
- **직전 PR이 이미 머지되었다면** 그 브랜치는 재사용하지 않는다.
  최신 main에서 다시 시작한다.

  ```bash
  git fetch origin main
  git reset --soft origin/main      # 작업 트리 내용은 유지하고 브랜치만 이동
  ```

  (작업 트리가 main과 이미 같은 내용이면 `--soft`, 아니면 `-B <branch> origin/main` 후 재적용)

## 커밋 메시지

```
<타입>(<범위>): <한 줄 요약 — 무엇이 달라졌는지>

증상 / 배경
  - 사용자가 무엇을 겪었는지, 또는 왜 필요했는지

수정
  - 무엇을 어떻게 바꿨는지

검증
  - 숫자로. "확인함" 금지
```

타입: `feat` `fix` `refactor` `docs` `chore`

**검증 절을 반드시 넣는다.** 나중에 이 커밋을 다시 볼 때 "무엇을 확인했는가"가 남는다.

---

## PR 본문

| 절 | 내용 |
|---|---|
| 증상 / 배경 | 사용자 관점에서. 코드 관점이 아니라 |
| 수정 | 표로. 대상 → 조치 |
| 검증 | **이전/이후 숫자 대비표** |
| 참고 | 이번 변경과 무관한 기존 이슈를 발견했다면 여기에 |

숫자 대비표 예:

| 항목 | 이전 | 이후 |
|---|---|---|
| JS 예외 | 30건 | **0건** |
| QR 표시 차시 | 1 / 31 | **31 / 31** |

## 자가 리뷰 체크리스트

머지 전에 스스로 본다.

- [ ] 검증 4단(A~D) 전부 통과, 통합 검사(E)도 통과
- [ ] `git diff origin/main --diff-filter=D` 비어 있음
- [ ] 배치가 학생용·교사용·묶음 **세 곳 모두** 일치
- [ ] 내부 작업용 분류가 학생 화면에 노출되지 않음
- [ ] 교사용 자료가 `.gitignore` 정책을 위반해 공개되지 않음
- [ ] 이번 변경과 무관하게 **새로 발견한 기존 결함**을 PR에 기록했는가
- [ ] 커밋 메시지·PR에 검증 숫자가 있는가

---

## 발견한 별건 처리

작업 중 **이번 요청과 무관한 결함**을 발견하면:

1. 고치지 않는다 (범위를 넘는다)
2. PR 본문 "참고" 절에 기록한다
3. 최종 보고에서 선생님께 알리고 **정리할지 물어본다**

> 실제 사례: 익힘책 작업 중 링크 5건 깨짐을 발견 → 보고 → "정리해줘" → 별도 PR로 처리.
> 묶음 작업 중 전역 충돌 발견 → 보고 → 별도 PR.
>
> 이렇게 하면 PR 하나가 한 가지 일만 하므로 되돌리기 쉽다.
