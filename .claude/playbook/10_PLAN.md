- 4·5·7번은 **되돌리기 비싼 결정**이다. 반드시 명시적으로 답을 받는다.
- 나머지는 기본값으로 진행해도 되며, 결과 보고에 가정을 한 줄로 적는다.
- 선생님이 "어떤 게 좋을까?"라고 되물으면 **추천안을 먼저 제시**하고 이유를 한 줄로.

## 작업 그래프 — 병렬 단위 정하기

**단원(또는 차시)이 병렬 단위다.** 단원끼리는 의존이 없으므로 독립 진행한다.

```
                ┌─ 추출 → 제작 → 검증 ─┐
스코핑 ─────────┼─ 추출 → 제작 → 검증 ─┼── 통합 → 감사 → 납품
                └─ 추출 → 제작 → 검증 ─┘
                  (단원 수만큼, 서로 기다리지 않음)
```

- **장벽(barrier)을 두지 않는다.** Ⅰ-1 검증 중에 Ⅱ-1은 제작에 들어간다.
- 통합 단계만 모든 단원 결과가 필요하다.
- 한 단원이 검증에서 실패해도 나머지는 계속 간다. 실패한 단원만 재시도.

**단원 수가 3개 이하면** 파이프라인을 만들지 말고 그냥 순차로 한다. 오버헤드가 더 크다.

## 리스크 점검

착수 전에 이 5가지를 확인한다.

| 리스크 | 확인 방법 | 걸리면 |
|---|---|---|
| 원자료 텍스트 추출 불가 (스캔 이미지) | `fitz`로 첫 페이지 텍스트 길이 확인 | OCR 또는 수동 입력 필요 → 일정 재산정 |
| 그림 문항 비율이 높음 | 문제 페이지 육안 확인 | 그림 1장당 크롭+확인 시간 계상 |
| 정답이 원자료에 없음 | 해설 페이지 존재 확인 | 전 문항 직접 계산 → 시간 3배 |
| 교육과정 범위 불명확 | 과목 프로파일 존재 여부 | `profiles/` 에 먼저 작성 |
